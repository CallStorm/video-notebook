# 视频知识工作台 · 需求说明

> 本文档分两层：
> 1. **功能面**（第一节到文末）：根据 Gemini Notebook 整理的产品形态与交互要求，**与 2026-10-16 原始版本完全一致**，未经用户书面确认不得改动。
> 2. **SaaS 子需求**（新增章节）：交付 Web SaaS 形态时需要的账号、视频生命周期、异步任务、存储、播放、多租户、分享、第三方依赖等子需求。

v1 范围：**严格对齐下方功能面**，并实现 SaaS 子需求中标记为 v1 的条款。**不扩功能面**（Audio Overview / FAQ / Timeline 等一律不在 v1 内）。

# 第一部分 · 功能面

## 首页

- 顶部有三个入口：我的笔记本、发现、集合。旁边可以搜索笔记本，可以在网格和列表之间切换。
- 「发现」是后续多人共享的入口。当前先做占位，打开是空页面。
- 「我的笔记本」里，右上角是「新建笔记本」。
- 每张卡片有图标、标题、日期、来源数量，以及一个更多菜单（修改 title、置顶、添加到集合、删除）。鼠标停在卡片上，会看到完整标题。点卡片进入笔记本。

## 集合

- 集合是单独一页，右上角是「新建集合」。
- 每张集合卡片有图标、名称、里面有几个笔记本，以及一个更多菜单（编辑、删除、图标）。

## 笔记本

打开后是三栏，顶栏是笔记本标题，以及新建笔记本。

### 左栏：来源

这里的文件就是视频。当前链接和上传都只支持视频。

- 添加来源：弹出一层。可以上传视频、贴视频网页（含 YouTube）、粘贴文字，也可以把视频文件拖进去。
- 创建笔记：点击创建，在右侧工作室显示编辑界面，可以写富文本。创建完成后，笔记进入左栏列表。

添加后，下面列表分成视频列表和笔记列表。每一条有三部分：

- logo：视频或笔记的图标
- 文件名
- checkbox。默认选中。问答和右侧工作室二次加工时，只用勾选中的来源。

点名称：

- 点的是视频：左栏上方显示概览，下方显示这条视频的字幕。
- 点的是笔记：在右侧工作室区域下方显示笔记内容。

### 中栏：对话

- 输入框是「提问，或让它生成点什么」。下方标出这次用了几个来源。
- 回答按资料来写，句中带编号。
- 鼠标悬浮在编号上，可以预览相关内容。
- 点击引用编号，左栏自动显示该来源的概览和下面的内容，并定位到相关位置。
- 回答下面有保存到笔记、复制。保存后的笔记进入左栏列表。
- 下面可以生成三个相关问题。

### 右栏：工作室

上面是一排生成入口：幻灯片、思维导图。下面是已经生成的结果列表。正在生成的可以删除。

## 思维导图

- 在工作室点击思维导图，弹出页面。可以选择语言、来源、主题，然后点击生成。来源列表默认带上左栏已勾选的来源。
- 工作室下方可以看到思维导图任务。生成好后可以点击打开。
- 打开后：
  - 左侧可以放大、缩小、全部展开、下载。左上角可以查看用到的来源。
  - 右上角可以展开，铺满屏幕。更多操作里可以删除。
  - 中间的图，点箭头展开或收起。点文字，会把问题发到对话里。导图保持打开。
  - 有父节点时：`Discuss what these sources say about {当前节点}, in the larger context of {父节点}.`
  - 没有父节点时：`Discuss what these sources say about {当前节点}.` 例如：`Discuss what these sources say about 灭佛之源：战争储备、财政危机与皇权神权.`
- 思维导图名称每次自动生成。

## 幻灯片

- 在工作室点击幻灯片，弹出页面。可以选择语言、来源，并描述想创建的幻灯片，然后点击生成。长度由 AI 判断，并给出一个建议长度。
- 生成好的幻灯片可以在右栏里滚动查看，也可以像思维导图那样展开铺满。
- 右上角更多菜单可以下载 PPT、PDF，或删除。

# 第二部分 · SaaS 子需求

> 本节为 Web SaaS 形态必需的下层能力。**所有 SaaS 子需求均为 v1 范围**，但**不增加功能面**。

## S1. 账号与权限

- **注册**：**不做用户自助注册**。账号由管理员在后台创建（见 S11），管理员录入姓名、手机号、初始密码并下发。
- 登录：**手机号 + 密码**。密码按行业实践做强度校验与加盐哈希（不在客户端做）。
- 首次登录：建议强制改初始密码（v1 用普通「修改密码」流程即可，无需过期校验）。
- 会话：服务器签发 JWT 或 Session Cookie；JWT 走 Refresh + Access 双 token 机制。
- 忘记密码：由管理员在后台重置（普通用户侧无自助找回入口，**系统内部使用**）。
- 账号注销：硬删除账号下所有笔记本、视频文件、字幕、笔记、Studio 产出，所有相关对象存储对象一并删除（异步队列处理，最终一致即可，但需要在 UI 给用户反馈）。
- 角色：`普通用户` 与 `管理员` 两种，定义见 S11。

## S2. 视频生命周期

### S2.1 上传

- 分片上传 + 断点续传：单文件超出阈值（默认 50MB，可配）走分片上传；小文件走普通 multipart。
- 格式白名单：`mp4 / mov / mkv / webm` 起步。`v1 开发期无单文件/时长硬限制`，但需要在 UI 给出大致预估（大小、时长）。
- 上传进度：客户端轮询或 SSE，前端显示百分比与已传输量。

### S2.2 通过 URL 抓取

- 支持 YouTube / Bilibili（**v1 这两家起步**），其他平台占位可扩展。
- 服务端 `yt-dlp` 队列：HTTP 入队后 worker 拉取，转封装为 mp4（必要时），落到对象存储。
- 状态机：`pending → fetching → transcoding → uploading → done`；任何阶段可进入 `failed`，并记录失败原因。
- 失败兜底：用户可以重试；或改成「提示我改为上传本地文件」。

### S2.3 元数据与存储分层

- 原始视频对象（按内容 hash 去重）。
- 元数据：标题、时长、来源（上传 / URL）、抓取源 URL、宽高、码率、对象存储 key、hash、上传时间、所有者、可见性。
- 元数据进 **MySQL 8.x**。

### S2.4 字幕来源链

每个视频的字幕按以下顺序取首个成功者：

1. 容器内嵌字幕轨道（mp4/mkv 自带）。
2. 平台伴生字幕文件（YouTube 字幕、B 站 CC 等，仅 URL 抓取链路）。
3. 服务端 ASR 转写（见 S3.2）。
4. 失败时给用户明确的「无字幕」提示。

## S3. 异步任务与 ASR

### S3.1 任务队列

- 所有转写、Studio 生成都走任务队列；前端获取任务 id 后轮询（或订阅 SSE）拿状态与结果。
- 任务状态：`queued / running / succeeded / failed / canceled`。
- 任务失败可重试；前端可显示失败原因与重试按钮。

### S3.2 ASR 流水线

- ASR 走 **adapter 模式**，接口最小集：异步提交 → 查询进度 → 拉取 SRT/JSON 结果。
- v1 默认实现：**OpenAI Whisper API**。
- 预留 adapter：**阿里云语音识别**、**字节火山引擎**（仅写空实现也可，但接口必须存在，方便后期接入）。
- 触发时机：视频入库且无字幕轨道时，进入自动检测调度。**目标语言策略：自动检测**（Whisper 自身具备自动检测能力；若 adapter 切换到不支持自动检测的厂商，需在 UI 显式让用户选）。
- 输出：以 **SRT（行级时间戳 + 文本）**落库，配套 JSON 用作行号 → 时间戳的索引。
- **失败重试**：可配置最大重试次数；超过则进 `failed`，用户可手动重试。

### S3.3 字幕后处理（拿到字幕后做什么）

> 这一节把字幕入系统之后的展示、检索、纠正、导出逐条定下来。

**S3.3.1 检索策略（v1 仅全上下文）**
- v1 走**全上下文**：每次对话把「左栏勾选的所有来源」的**完整字幕 + 已保存笔记**拼成一个 context 喂给 LLM。
- 抽象 `RetrievalStrategy` 接口：`buildContext(query, sources) → promptCtx`。v1 只实现 `FullContextStrategy`。
- **v1 不做**：向量嵌入、向量 DB、BM25、切片、重排序。**留接口位**，以后换 / 加 `EmbeddingRetrievalStrategy` 不动业务代码。
- 软上限：单次 query 上下文总 token 超过 **60K** 时，前端给出「上下文超过上限，建议减少勾选来源」的提示（**不阻断**，只是提醒）。

**S3.3.2 字幕错误纠正**
- **v1 不做行内文本编辑**（不开放「改这一行」入口）。字幕错误的处理方式是**重新转写**，而非手工改字。

**S3.3.3 重新转写入口**
- 来源页提供「**重新生成字幕**」按钮：
  - 触发新一次 ASR 任务（复用 S3.2 任务队列），可指定 adapter（默认走管理员当前 ASR 配置）。
  - 完成后**新字幕覆盖**旧字幕；旧字幕可选择保留为历史版本（v1 默认不保留，删除旧版以节省存储；预留 `keep_history` 选项位）。
  - 重新转写过程中仍可读旧字幕。

**S3.3.4 空字幕兜底**
- 三路字幕全部失败时，来源页给出「**暂无字幕**」提示 +「**重试转写**」按钮（可显示最近的失败原因）。

**S3.3.5 SRT 下载**
- 来源页「更多」菜单提供「**下载 SRT**」入口，下载当前字幕为 SRT 文件。

## S4. 对象存储

- v1：**服务端本地文件系统**（如 `/data/video-notebook/storage/<yyyy>/<mm>/<hash>`）。
- 抽象 `ObjectStorage` 接口：`put / get / delete / head / signedUrl`。v1 实现 `LocalFsObjectStorage`。
- 文件按内容 hash 去重；写入前先比 `hash`。
- 后期切到 S3/R2/阿里 OSS：换实现，业务层零改动。**v1 不需要现在就接，但接口要在。**

## S5. 播放链路

- 视频可走服务端流式（HTTP range）或 HLS。**v1 推荐直接 mp4 + HTTP range**，足够覆盖中等体量；体积巨大或带宽吃紧再切 HLS。
- 对象存储 URL：**走签名 URL**（v1 本地磁盘可走临时 token 代理，避免泄露磁盘路径）。
- **不**实现「点击字幕行 → 视频跳转到该时间戳」；**点击引用编号只跳转字幕行**（高亮当前行即可），视频位置保持不变。
- 播放器：原生 `<video>` 起步；若进度控制/字幕体验不够，再考虑 `video.js` / `plyr.js`。

## S6. 多租户数据隔离

- 所有数据表带 `owner_id`（账号）。
- 任何读取 / 写入都强制按 `owner_id` 过滤；后端用中间件统一注入。
- 公开笔记本：通过「分享」链产生的新访问形态，**不绕过 `owner_id` 隔离**，而是为分享 URL 生成独立的访问令牌（见 S7）。

## S7. 分享与协作

v1 形态：**作者可以将单本笔记本设置为「分享全员」**，开启后出现在「发现」入口，其他登录用户可浏览与只读访问。

**作者侧**
- 笔记本设置里有一个开关：「**分享全员**」。开启后：
  - 该笔记本出现在首页「**发现**」入口的列表中（带作者、标题、来源数、最近更新）。
  - **不**会出现在该作者自己的「与我共享」区域（与受邀共享区分开）。
- 关闭即从「发现」撤回。

**只读访问侧（其他人）**
- 「发现」列表可看到所有当前开启「分享全员」的笔记本。
- 点击进入只读视图：
  - 左栏：可看视频来源、可播放、可看字幕。
  - 中栏：**只展示作者的历史问答**；**其他人不能输入新问题**（输入框禁用且不发送请求）。
  - 右栏：可看 Studio 已生成的思维导图 / 幻灯片，可下载，不可触发新的 Studio 任务。
  - 笔记：可读作者保存的笔记，但不能创建/编辑。
- 没有任何写操作入口；后端也要禁止（写接口检查 owner_id 或是否本人）。

**不做（v1 范围外）**
- 不做受邀协作者、不做按手机号单独邀请链接、不做「与我共享」专属区域。
- 不做多人实时协作（不加 OT / CRDT）。
- 「**集合**」**不做多人共享**，仅作者自用。

## S8. 第三方依赖

- **ffmpeg**：转码、抽音频、字幕烧录等。
- **yt-dlp**：URL 抓取。
- **OpenAI Whisper API**：v1 默认 ASR。
- **minimax（Anthropic-兼容 API）**：v1 默认 LLM。LLM 调用要走 client abstraction，**最简实现够用即可**，但接口需留位便于以后切 Claude / 本地 ollama 等。
- **MySQL 8.x**：主存储（见 S9）。
- **无短信依赖**：管理员创建账号，**系统内部使用**，不需要外部 SMS。

## S9. 部署与运维

- **docker-compose 一键起**：包含 `web`（前端）、`api`（后端）、`db`（MySQL 8.x）、`worker`（异步任务 worker）、`storage`（本地卷挂载或未来对象存储客户端）。
- 健康检查、日志集中（JSON 行）、基础监控（容器存活 + 接口 5xx 报警）。
- `.env.example` 把所有需要的 key 列出来：`OPENAI_API_KEY`（默认 ASR）、`MINIMAX_API_KEY`、`MINIMAX_BASE_URL`（Anthropic-兼容）、`MYSQL_*`、`JWT_SECRET`、模型/ASR 主密钥（如需在 DB 加密存储敏感配置）。
- **系统内部使用**：无外部暴露公网、反向代理、短信通道等要求，部署在内网或单机即可。

## S10. 隐私与数据

- 单笔记本导出：zip（包含视频文件 + 字幕 SRT + 笔记 JSON + 引用关系）。**v1 仅做基本可用版**。
- 整账号数据导出：同上传 zip，按 GB 大小支持分批。
- 账号注销：见 S1。

## S11. 管理员角色

- **管理员**是 v1 的固定角色之一。普通用户无法自助成为管理员。
- 管理员登入后可见 `/admin` 路由；普通用户访问 `/admin` 一律 403。
- **管理员能力（v1 范围）**：
  - **用户管理**
    - 创建账号（姓名、手机号、初始密码、可选角色 = 普通用户或管理员）。
    - 重置密码。
    - 启用 / 禁用账号（禁用账号无法登录，资源不删）。
    - 列表查看 / 检索账号。
  - **模型配置**
    - LLM：provider（OpenAI / Anthropic / Gemini / 本地 ollama / minimax 等）、base URL、API key、模型名、超参。可配多套并支持「默认」与「针对账号 / 笔记本覆写」。
    - ASR：provider（OpenAI Whisper / 阿里云 / 字节 / 预留位）、API key、模型大小（small / medium / large-v3）、语言策略（自动检测 / 固定语言）。
    - 配置存数据库；**密钥加密存储**（设计阶段拍 AES-GCM 主密钥在 env 还是 KMS）。
  - **Skill 管理（Studio 用）**
    - 上传 Skill 包（zip，必含 `SKILL.md`），解压落服务端文件系统。
    - 编辑 Skill 元数据（name / description / version，不改目录内容）。
    - 下载、软删 Skill（被 Agent 引用的不允许删；内置 Skill 不允许删）。
  - **Agent 管理（Studio 用）**
    - 创建 Agent = 绑定 provider（v1 固定 claude_code）+ skill（可空）+ 模型名 + system_prompt + 超参 + 超时。
    - 启用 / 停用、设为「该 kind 的默认」。
    - 删除采用软删。
- 管理员在 `/admin` 页的更改写库后，**对所有用户即时生效**（不必重启服务）。**Worker 也需感知变更**（通过订阅 DB 变更 / 配置中心 / 定时拉取）。
- v1 不做的管理员能力：日志/审计、计费、操作记录、RBAC 细分。**留待 v2+**。

## S12. 已锁定的 v1 默认值一览

| 项 | 默认 |
|---|---|
| 形态 | Web SaaS |
| 部署 | docker-compose |

| 存储 | 服务端本地磁盘 |
| 上传边界 | 开发期无硬限制 |
| 分享 | 作者设「分享全员」→ 进「发现」只读视图（无写权限） |

| 计费 | 否 |
| 公网暴露 | 否（内部使用） |

# 附录 · 待设计阶段拍板的子项

这些**不阻塞**需求层，但**不设计完无法动工**。下一阶段进入设计时一起拍：

1. **前端框架**：React / Vue / Svelte / Solid。
2. **后端框架**：Node（NestJS / Fastify）/ Python（FastAPI）/ Go（Gin / Echo）。
3. **数据库**：已锁定 **MySQL 8.x**，本附录项仅需确认驱动/字符集/时区。
