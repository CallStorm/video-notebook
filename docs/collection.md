# 采集说明

影知把视频收进笔记本之后，由 **media-worker** 下载、出字幕、写概览，并刷新语义索引。产品明确支持的站点是 **哔哩哔哩**、**YouTube** 和 **抖音**。本地要先跑起 media-worker，见 [本地部署与开发](development.md)。三条入口怎么把链接送进来，见 [功能说明](features.md)。

关键词搜索只覆盖哔哩哔哩和 YouTube。抖音只能靠链接或分享文案入库，没有抖音关键词搜索。

## 从哪里发起

| 入口 | 哔哩哔哩 | YouTube | 抖音 |
|------|----------|---------|------|
| PC 网页搜索 | 按关键词搜索，点「加入」 | 同左 | 不支持 |
| PC 添加来源 | 上传本地文件，或粘贴链接 | 同左 | 粘贴链接。分享文案按空格或换行拆开，保留以 `http://` 或 `https://` 开头的片段 |
| 对外 Agent | `search` 之后，用户明确指定再 `add_url` | 同左 | `search` 不支持。用户给出链接后可以 `add_url` |
| 微信小程序 | 粘贴含链接的文案，抽出第一个 http(s) 地址 | 同左 | 主要用法：粘贴抖音分享文案 |

三条入口写入的是同一套笔记本。URL 来源先记为待抓取，再交给 media-worker。

## 入库之后

1. 链接来源进入队列。media-worker 开始下载时状态为抓取中（界面或接口里可见 `probing`），文件落盘后为 `ready`，失败为 `failed`。未完成的 URL 来源可以在 PC 上来源菜单里「重新抓取」。
2. 下载按地址分流，见下一节。直链媒体文件优先；其次是命中抖音域名规则的链接；其余交给 yt-dlp（哔哩哔哩、YouTube 走这里）。
3. 字幕按下面的顺序，有一种成功就不再往下走：
   - 哔哩哔哩 / YouTube：yt-dlp 若写下字幕文件（人工字幕或自动字幕，语言偏好为英语和中文），先作为平台字幕导入。
   - 否则抽取视频内嵌字幕。
   - 再否则用后台配置的语音转文字。
   - 抖音解析不返回字幕文件，因此只会走内嵌字幕或语音转文字。
4. 字幕就绪后，若后台开了自动概览，再生成概览，并刷新笔记本的向量索引。
5. 知识底稿不是采集的一步。对外 Agent 在任一来源仍在抓取或字幕未就绪时会拒绝 `generate_draft`，须 `ready_for_draft = true`。PC 上的提示是「字幕就绪后生成知识底稿」。

本地上传不经过平台下载，直接从内嵌字幕开始，没有则语音转文字。

需要本机 `ffmpeg`。YouTube 建议安装 Deno（没有 Deno 时会尝试 Node），用来解 yt-dlp 的播放器脚本。思维导图、幻灯片、阅读页不在这条流水线里，它们走 studio-worker。

## 地址怎么分流

下载时的判断顺序：

1. 路径以 `.mp4`、`.webm`、`.mkv`、`.mov`、`.m4v` 结尾：按普通 HTTP 文件下载，不走 yt-dlp，也不走抖音解析。
2. 主机名命中抖音解析的域名规则（域名本身或子域名，多条同时命中时取得更长的那条）：交给抖音解析服务。
3. 其他地址：yt-dlp，只取单个视频，不拉整份播放列表。合并格式优先 mp4。

未命中抖音规则、也不是上述直链后缀的地址都会尝试 yt-dlp。产品承诺支持的站点仍是下面三个；不要把 yt-dlp 碰巧能打开的其他网站当成已支持平台。

后台 **内容流水线 → 抓取** 里的并发、单条超时和分块并行，作用于 yt-dlp 下载（哔哩哔哩 / YouTube）。抖音文件由解析服务给出播放地址后再下载，不使用这套分块参数。超时也可以限制抖音解析的等待时间。

## 哔哩哔哩

- **搜索**：笔记本内网页搜索和 Agent 的 `search` 先请求哔哩哔哩网页搜索接口。没有登录 Cookie 时会带访客标识。接口失败（常见是风控，例如 HTTP 412）时，再改用 yt-dlp 的 `bilisearch`。两边都失败时，提示到后台为哔哩哔哩配置 Cookie 后重试。
- **下载**：`bilibili.com`、`b23.tv`、`bilivideo.com` 识别为哔哩哔哩，用 yt-dlp 下载。短链可以粘贴。
- **Cookie 与代理**：在 **后台配置 → 内容流水线 → 网络** 为哔哩哔哩上传或粘贴 Netscape Cookie，并打开「启用」后，才会用于搜索和抓取。代理类型可以是 `http`、`https`、`socks5`、`socks4`，并且要勾选作用到哔哩哔哩。未启用的 Cookie 不会带上。

## YouTube

- **搜索**：yt-dlp 的 `ytsearch`。若已启用 YouTube Cookie 或把代理作用到 YouTube，搜索和下载都会带上。
- **下载**：`youtube.com`、`youtu.be` 识别为 YouTube，用 yt-dlp。播放器客户端使用 `default` 与 `web_embedded`。出现要求登录或确认非机器人时，到「网络」为 YouTube 启用 Cookie 后再抓。若提示客户端需要重新加载，先确认本机有 Deno 或 Node，并更新 yt-dlp，然后重新抓取。
- **字幕**：优先保存英语和中文（`en`、`zh-Hans`、`zh-Hant`、`zh`、`en-US`）的人工或自动字幕。没有可用字幕文件时，再走内嵌字幕或语音转文字。
- **代理**：访问 YouTube 通常需要在「网络」里启用代理，并勾选 YouTube。

## 抖音

抖音没有关键词搜索。PC 粘贴链接、小程序粘贴分享文案、Agent 在用户给出 URL 之后 `add_url`，都是把链接送进同一条解析路径。

- **域名**：默认规则是 `v.douyin.com`、`douyin.com`、`iesdouyin.com`。可在「网络 → 抖音解析」里增删，最多 30 条。可用一条链接试匹配，看会不会走解析。
- **解析服务**：命中规则的链接交给已部署的解析服务：请求其 `/api/v1/parse`，未完成时按任务编号轮询。代码里的客户端对应 Douyin_TikTok_Download_API，默认只转发上面的抖音域名。默认地址 `http://127.0.0.1:8001`，需要填写 API Key；Key 只保存在服务器上。未配置地址或 Key 时，抓取失败并提示到「抓取与网络」补齐。页面上可以「测试连接」。
- **只收视频**：图文和图集、直播不能作为视频来源。解析结果里没有可下载地址时同样失败。
- **不走平台 Cookie / 代理**：哔哩哔哩和 YouTube 的 Cookie、代理不作用于抖音解析。抖音解析服务按它自己的配置访问抖音。
- **字幕**：解析结果不带字幕文件。视频落盘后走内嵌字幕，没有则语音转文字。

分享文案本身不会整段交给解析服务。PC 只收下以 `http://` 或 `https://` 开头、被空格或换行分开的片段；小程序从整段文字里抽出第一个 http(s) 链接。
