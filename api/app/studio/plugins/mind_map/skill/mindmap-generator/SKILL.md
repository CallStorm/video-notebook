# 思维导图生成

根据用户给出的文件（可以是目录路径，或对话中上传的文档），自动完成"提取文本 → 生成大纲 → 生成可交互思维导图"三步，并呈现最终 HTML 文件。

## 何时使用

- 用户说"生成/画思维导图""根据这本书/文档做大纲和导图""把这份材料整理成树状导图"等。
- 输入为单个文档文件，或含文档的目录。

## 工作流程

### 1. 解析输入

- 若输入是**目录**：用 Glob/ls 列出其中文档（`.epub`/`.pdf`/`.docx`/`.md`/`.txt` 等），挑出最主要的文本类文件；若多于一个，先向用户确认用哪一个，或默认取体积最大/最相关的一个。
- 若输入是**单文件**：直接使用。
- 记录文件名（去扩展名）作为导图根标题与输出名前缀。

### 2. 提取文本

运行技能脚本 `scripts/extract_text.py`：

```bash
python scripts/extract_text.py <输入文件> --out /tmp/book.txt
```

- 支持：`.epub`（标准库 `zipfile`，零依赖）、`.txt`/`.md`（直接读取）、`.pdf`（需 `pdfplumber`/`pdfminer`，缺失会提示安装）、`.docx`（需 `python-docx`，缺失会提示）。
- 提取后阅读文本，把握全书/全文结构与核心论点（长文本先通读关键章节）。

### 3. 生成结构化大纲

基于文本内容，产出一份**标准 Markdown 标题层级**的大纲，写入 `<前缀>_大纲.md`：

- `# 一级`（书名/主题，作为导图根）
- `## 二级`（章/大模块）
- `### 三级`（节/子主题）
- `#### 四级`（要点）
- 列表项（`- `）可作为所属标题的子节点。
- 节点可用 `主标题：副说明` 或 `主标题——副说明` 的形式带一行副标题。
- 大纲可混用以下结构，`build_mindmap.py` 均能正确解析：
  - 标题层级 `#`/`##`/`###`/`####` 决定层级；
  - **无序列表** `- ` / `* ` 与**有序列表** `1. ` / `2、` 都作为"最近标题"的子节点，同级列表项互为兄弟、不嵌套；带前导缩进的列表项视为更深一层（如有序项下的 `- `）；
  - **表格** `| A | B |` 数据行解析为"节点+副标题"（首格=文字、次格=副标题），表头行与 `|---|---|` 分隔行自动跳过；
  - `---` / `***` 分隔线自动跳过；`>` 引用块在首个二级分章（`##`）之前视为元信息跳过，其后出现的（如文末"一句话总结"）作为总结节点挂到主根下；
  - 节点文字中的 `**粗体**`、`*斜体*`、`` `代码` `` 标记自动去除。
- 重点：提炼论证逻辑与可操作要点，而非简单复刻目录。

#### 3.1 附「内容简介」（仅入大纲、不进导图）

在"关于本书 / 作者介绍"这一节末尾，追加一个 **`### 内容简介`** 小节，用**约 300 字**概述全书：

- 成书性质（专著 / 编著 / 思想合集等）；
- 各篇（或各卷）的核心主张与逻辑主线；
- 阅读价值与定位。

该小节是**大纲专属内容**：标题必须含"内容简介"字样，`build_mindmap.py` 会自动跳过它，因此思维导图不会出现此节点——**请勿把它写成其它标题层级**，以免误入导图。写作顺序不限（先写简介再构建、或先构建再补简介均可），构建脚本都会排除它。

### 4. 构建可交互思维导图

运行 `scripts/build_mindmap.py`，它会解析大纲的标题层级、组装嵌套数据、注入 `assets/mindmap_template.html` 并输出：

```bash
python scripts/build_mindmap.py <前缀>_大纲.md <前缀>_思维导图.html --title "书名"
```

- 脚本自动处理单根/多根、标题层级、无序/有序列表、表格、引用块与分隔线；`--title` 覆盖根标题，`--sub` 覆盖根副标题。
- 产物为纯 HTML+SVG，离线可用，支持：点击折叠/展开、滚轮缩放、拖拽平移、展开全部/折叠分支/重置视图、**导出 PNG**（自动展开全部并以 2 倍清晰度下载整张导图，导出后还原当前视图）。

### 5. 呈现

调用 `present_files` 呈现生成的 `*.html`（内置浏览器预览），并简要说明导图结构与用法。

## 节点数据格式（供手动生成时参考）

`assets/mindmap_template.html` 读取全局变量 `window.MINDMAP_DATA`：

```js
{ text:"根标题", sub:"根副标题(可选)", children:[ { text:"分支", sub:"说明", children:[ ... ] } ] }
```

`build_mindmap.py` 已自动完成此转换，通常无需手写。若需手动微调，直接编辑生成的 HTML 中 `window.MINDMAP_DATA` 所在行即可。

## 注意事项

- **目录输入**：多文档时先确认目标文件，避免误处理。
- **超大文本**：epub/pdf 可能很长，提取后先通读关键章节再写大纲，保证提纲有提炼。
- **布局已校准**：模板已修复最底层节点纵向重叠（按节点自身高度+间距排布）与文字溢出（按真实字号估算宽度），无需再调。
- **第三方库缺失**：pdf/docx 提取若失败，提示用户安装对应库，或请用户提供纯文本。
- **中文路径**：Windows 下运行脚本时优先使用 WorkBuddy 托管的 Python（避免系统编码问题），路径含空格用双引号包裹。

## Studio 笔记本用法

当本技能被 Studio「思维导图」任务绑定时：

- 只交付 `outputs/mindmap.md`（markmap Markdown）与约定的 Studio `MANIFEST.json`，**不要**再走 HTML/全书目录交付流程。
- 优先遵守 prompt 中的「本次主题硬约束」与 `inputs.json` 的 `topic` / `focus_mode` / `extra_constraints`。
- `focus_mode=action`（默认）时按主题裁剪，不要铺成全书大纲；`outline` 才做全片/全书结构。
